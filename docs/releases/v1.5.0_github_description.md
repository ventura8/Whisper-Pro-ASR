# Release v1.5.0 - PARAKEET and CANARY: NVIDIA NeMo Engines

Two new opt-in ASR engines run NVIDIA's NeMo models through onnx-asr: **PARAKEET**
(Parakeet-TDT-0.6B-v3) and **CANARY** (Canary-1B-v2). Both cover 25 European languages.
A Whisper companion on `ASR_MODEL` serves language detection and every other language, so
`/detect-language`, Bazarr and every other API caller see the same contract as before.
**The default engine is unchanged** (`ASR_ENGINE=AUTO` still resolves to FASTER-WHISPER),
and so are the API and the task statuses. Two things change for every engine: the scheduler
now sends idle work to the fastest idle unit kind, and the dashboard's accelerator-load
figure follows where work really runs (see *Scheduling and monitoring*).

---

## Highlights

### PARAKEET and CANARY engines

- `ASR_ENGINE=PARAKEET` or `CANARY`. One engine per hardware unit, like every other
  engine; inside it are the NeMo model and a Faster-Whisper companion.
- **Routing per decode call** (`[NeMo] route=nemo|whisper reason=...` in the log): a
  language outside the model's 25 goes to Whisper, as does a call with no language. NeMo
  models never fail on an unknown language; they quietly transcribe it as the nearest one
  they know, so they are never given one. Translation goes to Canary natively, and to
  Whisper under Parakeet.
- **Decoding by speech region and pause/resume work unchanged.** The engines honour
  `clip_timestamps`, split anything over `NEMO_MAX_CHUNK_SEC` (20 s) at its quietest point,
  and yield segments a batch at a time, so preemption stops them at the next batch.
- **Timestamps:** Parakeet's token times become word timestamps and lines (at most 7 s and
  84 characters). Canary reports no times, so its lines are spread across their chunk by
  length and wrapped at 84 characters.
- **Devices:** CUDA, and Intel GPUs through ONNX Runtime's OpenVINO provider; NPU and AMD
  units run the model on the CPU. Providers are always named explicitly, and the startup
  banner reports the one actually in use.
- **Supply chain:** `NEMO_MODEL` can only name a catalog entry, and each entry is pinned to
  one Hugging Face revision. Provisioning downloads it and integrity-checks the result,
  never onnx-asr. The engine checks the pinned files again at load and refuses to start
  without them, so a failed provisioning can never let onnx-asr fetch the repository head.
- **Settings:** `NEMO_MODEL`, `NEMO_QUANTIZATION` (AUTO = fp32 on accelerators, int8 on
  the CPU), `NEMO_MAX_CHUNK_SEC`, `NEMO_BATCH_SIZE`, `NEMO_GPU_MEM_LIMIT_MB`, and
  `NEMO_COMPANION_DEVICE` (CPU keeps the companion off a card too small for both). A CUDA
  out-of-memory error at load falls back to the CPU. Mid-decode, a batch that runs out of
  memory is retried one chunk at a time, and a chunk that still does not fit is decoded on
  a CPU copy while the engine stays on the card.

### Scheduling and monitoring

- With several idle units, a task goes to the fastest kind
  (`engine_registry.AUTO_DEVICE_PRIORITY`). Units of the same kind keep FIFO rotation. This
  matters once one engine drives two vendors: PARAKEET ran 123x real time on a CUDA card
  and 9x on the iGPU beside it.
- The dashboard counts a NeMo engine's work as accelerator load only where it really runs.
  Language detection on an Intel unit is the CPU-bound companion's work.

### Engine evaluation

`docs/ASR_ENGINE_EVALUATION.md` records the measurements behind keeping FASTER-WHISPER the
default, and the benchmark harness that produced them (`tests/real_audio/test_engine_benchmark.py`,
`scripts/remote_validate.sh --suite bench|codeswitch|longform`). On an RTX 5090, Parakeet
decodes about 6.5x faster than Whisper large-v3, at a WER about three points higher on the
matrix clips. Canary sits between them on both. Canary also translates a short foreign line
into the language detection gave its region, rather than transcribing it, which makes it
the weaker choice for code-switched material.
