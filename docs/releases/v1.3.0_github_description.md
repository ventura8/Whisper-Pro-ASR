# Release v1.3.0 - Process Isolation, Hardware-Independent Engine Selection, and a Real-Audio Validation Layer

This release moves every vendor runtime out of the API process, makes engine selection
independent of the hardware it runs on, and adds the multilingual test corpus and remote
validation tooling that found most of the defects fixed below.

The theme running through it is a single failure mode: **a service that reports an
accelerator while quietly running on the CPU.** Several separate instances of that are
fixed here, and the guards added alongside them exist so it cannot happen silently again.

---

## Highlights

### Process Isolation (Architecture Change)

Engines and vocal separation now each run in their own worker process, behind a shared
duplex channel (`modules/inference/engines/worker_channel.py`).

Vocal separation is isolated on supported units only. Pre-Alchemist Intel graphics are the
exception: the UVR worker dies with SIGSEGV on Intel UHD, so isolation is gated on the
OpenVINO-reported GPU generation (`isolation_policy.py`) and separation stays in-process
there -- which means the crash containment described below does not apply on those hosts.

Three reasons, in order of weight:

- **Device-memory reclamation.** Killing a process is the only way to return a
  CUDA/ROCm/OpenVINO context's memory to the OS. In-process teardown reclaims none of it:
  an idle purge logged `CUDA VRAM=193 MB -> 193 MB (Delta: +0 MB)`.
- **Crash containment.** A native segfault in CTranslate2, ROCm or the OpenVINO GPU plugin
  used to kill the API process. It now kills one worker, which respawns on the next call.
- **Mutually exclusive runtimes.** One interpreter cannot hold a CUDA context and an
  OpenVINO GPU context, nor a CUDA torch build and a ROCm one. Separate processes are the
  only way to run them together — which is what lets a hybrid host drive both cards.

Controlled by `ASR_ISOLATE_ENGINES` and `ASR_ISOLATE_PREPROCESSING` (both on by default).
The channel handles generation stamping so a cached handle cannot outlive the worker that
issued it, segment streaming, and cooperative cancellation across the process boundary.

### Engine Selection No Longer Depends on the Hardware

- **`ASR_ENGINE=AUTO` now resolves to `FASTER-WHISPER` on every host.** Previously AUTO
  picked a different engine per accelerator, which made the decoding behaviour — and
  therefore the transcript — a property of whichever machine a request landed on. One
  engine everywhere makes a deployment reproducible across a fleet.
- **`HYBRID_ENGINES` is off by default and opt-in.** On a host with both a CUDA/AMD GPU
  *and* an Intel GPU/NPU, `true` runs each unit's native engine in its own worker so both
  accelerators stay busy — at the cost of reintroducing per-unit engine variation.
- **`ASR_DEVICE` is now aligned with what the engine can actually drive.** CTranslate2 has
  CUDA and CPU backends and nothing else, so on Intel or AMD the device is reported as CPU
  rather than naming a device it cannot address. The unit stays in the pool for vocal
  isolation, which reaches it through ONNX Runtime.

Accelerator-specific engines remain available; they are now asked for explicitly
(`ASR_ENGINE=INTEL-WHISPER`, or `OPENAI-WHISPER` with the `amd-rocm-torch` image).

### Code-Switched Audio

- **Per-window language re-detection** (`multilingual=True`) for auto-detected requests.
  An explicitly requested language keeps the single-language path, because the flag
  overrides the request *and* misreports what it returned.
- **Gap-filling re-transcription** (`modules/inference/runtime/gap_filling.py`): speech VAD
  confirms but no segment covers is re-transcribed in its own detected language. Fixes the
  recorded dropped-code-switched-legs defect and, as a side effect, segments stopping short
  of the clip end. Costs one VAD pass and nothing further when there are no gaps.
- **`segment_languages`** is reported per response, so a code-switched file says where each
  language was found.

### Bug Fixes

- **Transcripts were being truncated on the way to the client.** History truncation mutated
  `task_data["result"]` in place — the same object the request handler returns — while
  `log_completed_task` only shallow-copied afterwards. Measured on a 20-minute clip: 169
  segments reaching 1202s were delivered as 100 segments ending at 765s. This had been
  recorded as an ASR "coverage" defect for some time; it was never the ASR.
- **AMD acceleration was silently disabled in every image.** ROCm pruning deleted
  `librocsolver.so.0`, which the ONNX Runtime ROCm provider links directly. ONNX Runtime
  treats a provider that fails to `dlopen` as merely unavailable — `get_available_providers()`
  still listed `ROCMExecutionProvider` while every model ran on the processor.
  `scripts/docker/verify_ort_provider_links.sh` now fails the build on an unmet provider
  dependency, so this class of fault cannot ship again.
- **OpenVINO reported an NVIDIA card as a plain Intel `GPU`**, which registered it as an
  Intel unit, handed it `INTEL-WHISPER`, and returned 500 for every request routed there —
  31 failures across the real-audio suite on the `full` image. Vendor identity now comes
  from `DEVICE_ARCHITECTURE`'s PCI vendor id.
- **The Intel NPU built a pipeline it could not execute.** The service started healthy,
  printed `ASR Runtime: OpenVINO (NPU)`, and failed every request. `modules/core/device_probe.py`
  inspects the OpenVINO IR for dynamic shapes — metadata, not a trial run — and ASR falls
  back to the CPU while the NPU keeps doing preprocessing, which it does run.
- **The ONNX variant was chosen from `ASR_DEVICE` before `ASR_PREPROCESS_DEVICE`.** On a
  hybrid NVIDIA+Intel host this loaded onnxruntime-gpu, which carries no OpenVINO provider,
  so `ASR_PREPROCESS_DEVICE=GPU` ran UVR on `CPUExecutionProvider` while the logs named the
  iGPU — 0.48x against 2.40x, five times slower while claiming acceleration.
- **Runaway decoding on the Intel engine.** `repetition_penalty` (not
  `no_repeat_ngram_size`, which `WhisperGenerationConfig` accepts and silently ignores)
  breaks the loop. Applied to greedy decoding only: OpenVINO GenAI rejects it under beam
  search with a hard error, which is the CPU path and the NPU-fallback path.
- **`openai-whisper` language detection failed on every short slice**, because the audio was
  not padded to the encoder's 30-second window before the mel was built. Gap-filling detects
  on sub-second slices, so this recovered nothing on that engine while still returning 200.
- **A full temp volume aborted startup** instead of falling back to persistent storage.

### Vocal Separation Is Off By Default

Measured on an RTX 5090, two runs per mode, byte-identical:

| | off | on | |
| --- | ---: | ---: | --- |
| clean speech overlap | 0.9469 | 0.9469 | no gain at all |
| harder tail languages | 0.7994 | 0.7826 | loses 1.7 points |
| window misses (of 118) | 54 | 55 | |
| hallucinated quiet (of 25) | 12 | 10 | its one real win |
| long-form RTF | 0.063 | 0.110 | 76% slower |

76% more compute to remove two hallucinated windows in twenty-five. Still worth enabling
for music-heavy source material, which is not what the corpus represents.

### Intel: Vocal Isolation Out of Process, Gated by GPU Generation

Isolated UVR separates at 4.6–5.0x through `OpenVINOExecutionProvider` on an Arc 140T,
against 0.25x when the in-process manager falls back to the CPU provider. It is not safe
everywhere: on Intel UHD Graphics the worker dies with SIGSEGV, intermittently — the first
request succeeds and a concurrent pair kills it, so a single green run proves nothing.

The variable is the GPU generation, not the software. `DEVICE_ARCHITECTURE` separates them
cleanly (`v12.0.0` on the part that crashes, `v12.74.0` on the part that does not), and
`modules/inference/pipeline/preprocessing/isolation_policy.py` gates on Alchemist-or-newer.
Anything unidentifiable keeps the in-process manager, because guessing wrong costs a native
crash rather than a slow path.

### Performance

- **Compiled-kernel caches now persist** across container restarts (SYCL, NEO, CUDA, Triton,
  Numba, all under `model_cache/kernel_cache/`). Intel cold start fell from 517.8s to 39.7s.
- **`ENABLE_LD_REQUEST_COALESCING`** collapses identical concurrent `/detect-language`
  requests onto one execution.

### AMD / ROCm

- Build-time verification that no bundled ONNX Runtime provider has an unmet dependency,
  with a documented allowlist for libraries supplied at runtime (`libcuda.so.1`, injected by
  the container toolkit) or deliberately absent (TensorRT, `libpython` for ROCm's unused
  Python bindings).
- `gfx1036` (the display iGPU in desktop Ryzen parts) is documented as unusable and why:
  `HSA_OVERRIDE_GFX_VERSION=10.3.0` gets ONNX Runtime's own kernels running correctly on it,
  then fails in rocBLAS, whose upstream Tensile library has never included that architecture.
  A GPU that can add but cannot multiply matrices is of no use to Whisper or UVR.

### Real-Audio Test Matrix

A generated multilingual corpus replaces the single English fixture: 40+ languages via Piper
and MMS-TTS, code-switched clips, degraded and malformed audio, and a 20-minute long-form
stress clip. Rendering is content-addressed and deterministic (the manifest pins the VITS
noise terms to zero), so committed fixtures round-trip with an empty diff.

- `scripts/audio_matrix/` — the generator; `scripts/generate_fixtures_docker.sh` runs it in a
  container so the TTS toolchain never touches the host.
- `tests/real_audio/` — accuracy, contract-abuse, degraded-input and long-form suites.
- The long-form clip has a **natural** layout profile measured from two genuinely
  code-switching films, because the original layout made utterance segmentation look far
  easier than it is: ~60% of real turns are separated by less than a VAD split threshold.

### Remote Hardware Validation

This machine cannot validate silicon it does not have. `scripts/remote_validate.sh` points at
a host that does — preflight, hardware audit, sync, build, run, and a tiered test suite —
with `scripts/validation_matrix.sh` driving several machines in parallel from an
operator-local plan (`.validation-matrix.conf`, gitignored, since it names hosts). Windows hosts are
driven through WSL2. Setup helpers exist for Linux, Windows and macOS in both shell and
PowerShell. See `docs/REMOTE_VALIDATION.md`.

It also carries the project's first controlled engine comparison — one machine, one image,
one corpus, only `ASR_ENGINE` changed:

| metric | FASTER-WHISPER | WHISPERX | OPENAI-WHISPER |
| --- | ---: | ---: | ---: |
| mean word overlap (24 clips) | 0.8675 | **0.8719** | 0.8716 |
| long-form RTF | 0.0299 | **0.0134** | 0.1179 |
| 24 short clips, wall clock | **26.1s** | 34.5s | 405.5s |
| hallucinated quiet windows (of 25) | 8 | **0** | 11 |
| window misses (of 118) | **56** | 109 | 89 |

### Images

- The **`full`** image is the default build target again, and carries every vendor's ONNX
  Runtime, so one tag runs on whatever hardware the host turns out to have.
- Images stamp `WHISPER_IMAGE_EDITION`, reported alongside `VERSION` on the dashboard —
  two containers can run the same version with very different accelerator support.

### Code Quality

- Every Python module is inside the project's 600-line limit; `config.py`, `model_manager.py`
  and the preprocessing package were split along their existing seams
  (`config_resolution`, `config_paths`, `config_model_paths`, `gap_filling`,
  `preprocessor_pool`, `isolation_policy`, `init_locks`).
- `pylint` 10.00/10 with no messages, `ruff` format + check, `flake8`, and PowerShell
  ScriptAnalyzer all clean.

## Known Limitations

- **AMD ROCm remains unverified on supported silicon.** The paths are implemented and
  reasoned through; the only Radeon available for testing was a `gfx1036` integrated part,
  which is not in the shipped ROCm kernel set.
- **The Intel NPU cannot execute Whisper.** It is detected, kept in the pool, and used for
  vocal isolation, which it does well. ASR on that unit runs on the CPU.
- Two long-form defects remain open and are tracked in the test suite as known defects:
  window misses and hallucinated speech in quiet passages.

## Verification

- **Full local suite**: 1690 passed, 0 failed, inside the Docker test image.
- **Intel NUC** (Core Ultra, Arc iGPU + AI Boost NPU): accuracy suite passing; UVR isolated
  on the iGPU through `OpenVINOExecutionProvider`.
- **RTX 5090 host** (NVIDIA + integrated Radeon): engine comparison, vocal-separation
  measurement, and long-form stress runs.
- **Windows 11 / WSL2** on the same host: the remote path exercised end to end.
- A passing suite proves decoding worked, not that the accelerator was used. Accelerator
  claims in this release are backed by device-side evidence — provider names, `nvidia-smi`
  compute apps, `intel_gpu_top`, or the worker's own reported provider.
