# Release v1.5.1 - Bazarr uploads without media mounts

## Summary

Fixes the production failure mode where every Bazarr job returned `No audio source provided` when media volumes were not mounted and `/tmp/whisper` was not writable by the service user (Portainer/custom compose with `tmpfs` size but missing `mode=1777`).

Media mounts remain an optional zero-copy optimisation. The upload path is the supported default.

## Fixes

- **Unwritable `TEMP_DIR` fallback**: `resolve_temp_dir` / `_temp_dir` now check writability before free space and fall back to `PERSISTENT_TEMP_DIR` (or system temp) instead of silently failing materialization.
- **Approved roots for persistent temp**: `get_approved_roots()` includes `PERSISTENT_TEMP_DIR` so materialized uploads that landed there are accepted.
- **Trust server-materialized uploads**: `MaterializedUploadPath` is used without re-applying the caller-facing approved-roots gate (avoids a crash when re-copying a path we just wrote).
- **Clearer materialization errors**: failed upload writes log the real cause instead of collapsing into `No audio source provided`.

## Tests

- New e2e module `tests/integration/test_bazarr_upload_without_mounts_e2e.py`: detect-language and ASR with unresolvable `video_file`, plus unwritable `TEMP_DIR` fallback.
- Unit coverage for writability fallback in `resolve_temp_dir` / `get_temp_dir`.
- Compose pin: `tmpfs` must be `/tmp/whisper:size=2G,mode=1777`.

## Ops note

If you deploy outside the repo compose (e.g. Portainer), keep:

```yaml
tmpfs:
  - /tmp/whisper:size=2G,mode=1777
```

`size=2G` alone is not enough after a compose restart.
