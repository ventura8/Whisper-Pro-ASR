# Release v1.4.0 - Decoding by Speech Region, and a Language for Every Segment

Whisper commits to one language per decode window. Left alone that window is 30 seconds of
whatever the VAD compacted together, so on audio that changes language faster than that, the
decoder picks one language for the lot and renders the rest of the window in it.

This release makes the speech region the decode window, decides each region's language
before decoding, and reports the language of each segment rather than only of the file.

---

## Highlights

### Segment-First Decoding

`ASR_SEGMENT_FIRST` (default **on**, FASTER-WHISPER only) scans for speech regions, detects
the language of each before decoding, groups consecutive regions of one language into runs,
and decodes each language in its own call -- told its language outright, one clip per
region -- so a decode window can no longer span a language change and the decoder is never
left to guess a language from one line. Measured on a 20-minute, 10-language clip that
switches every 7.6 seconds:

| | before | after |
| --- | ---: | ---: |
| windows transcribed in the wrong language | 67 / 118 | **0 / 118** |
| quiet windows filled with invented speech | 11 / 25 | **0 / 25** |

`quiet` improving is the same mechanism rather than a second fix. Clips exclude the silence
between them, so the decoder is never handed a silent window to invent speech into.

The runs are what make this safe on the case most libraries are made of: a film in one
language. Measured on 21 real monolingual films, decoding by region with the decoder
re-detecting each clip labelled a **median 20% of the speech** as another language -- one
line of dialogue is about a second, and language detection on a second of audio is
confidently wrong one time in five, almost always toward a neighbour (Russian as Ukrainian,
Norwegian as Swedish). Grouped into runs, with a block in another language needing 3 s of
confident speech before it counts (`SEGMENT_RUN_MIN_SWITCH_SEC`), that is **1.1%** --
under the 2.7% of whole-file decoding -- and the language reported for a segment is the
language it was decoded in by construction.

Applies to every auto-detected request and to **every translation**. A translation comes out in
English whatever was spoken, so a `language=` on it names the main audio, not the output: a
subtitle client that sends the track's language and asks for English gets each scene
translated from the language it was spoken in. Only a transcription with an explicit
`language=` keeps the single-language path exactly as before -- that language is what the
caller asked to read.

### A Language Per Segment

`ASR_SEGMENT_LANGUAGES` (default **on**) reports `segment_languages` per run -- one span per
stretch of speech decoded in one language, plus a span for any gap filled in another -- rather
than one entry for the whole file, and stamps each segment with the language of the span its
midpoint falls in (the file language where none does). No shipped engine offers this --
faster-whisper picks a language per window and never says which -- so it is measured directly,
at one encoder pass per clip, before the clips are grouped into runs.

It is deliberately **not** gated behind a whole-file "is this multilingual" check. Every such
signal was measured and reads a genuinely code-switching film as monolingual: the sampling
montage takes a handful of windows across two hours and the localised foreign passages fall
between them. Gating on one would label the synthetic fixture and miss every real film.

### Force Transcription

`ASR_FORCE_TRANSCRIPTION` (default **off**), or `force_transcription=true` on a request:
one subtitle in the film's language for a film that switches. The runs in the file's
language -- the one the request named, or the detected one -- are transcribed as spoken;
every run in another language is **translated into English**, the only target Whisper has.
A Romanian film with Turkish scenes, requested as Romanian, comes back as Romanian dialogue
with the Turkish scenes in English, where a plain transcription decoded the Turkish under
the Romanian token into noise. Gaps follow the same rule as the run they sit in. Measured
leg by leg on the six code-switched clips (`test_forced_transcription_keeps_the_named_language_and_translates_the_other`).

### Code-Switched Audio

A file whose two halves are different languages used to come back with one half missing. On
FASTER-WHISPER all six fixtures now return both halves:

| clip | before | after |
| --- | ---: | ---: |
| `mix_en_es` | 0.38 | **0.75** |
| `mix_hi_en` | 0.31 | **0.96** |
| `mix_zh_en` | 0.21 | **0.88** |
| `mix_en_fr`, `mix_de_en`, `mix_ar_fr` | one leg each | **1.00** |

### A Long-Form Fixture Laid Out From Real Film

The synthetic fixtures had never been measured against the media they stand in for. Doing
so -- the same VAD the suite scores by, over nine excerpts from a real library, numbers only
-- showed the fixtures were wrong on every axis that matters: lines three times too long,
scenes three times too many lines, and a music-and-ambience bed **18 dB quieter** than a
real film's, where the score sits 2.6 dB under the dialogue and sometimes above it. Every
`quiet` number to date was measured against near-silence, a case real media never presents.

`longform_film` is laid out from those measurements: 40 new one-line clips in short scenes
with a long tail, passages over a minute long, and a synthesized bed at a per-scene level
drawn from the measured range, calibrated by re-measuring until it landed where film has it
(3.4 dB). `longform_film_mono` is the same layout in one language -- the library's common
case, which no fixture had -- and both carry a new assertion: the language reported for
each line must be the language spoken. Two more are shaped from 54 further excerpts:
`longform_film_bookends` has a film's opening (105 s of logo and title music before the
first line, on a median film), a long passage inside and its credits (265 s), and
`longform_episode` a television episode's cold open, a title sequence and tighter scene
gaps -- the longest stretches of loud non-speech the decoder ever sees, which no fixture
had. All run alongside the stress grid and the natural profile; `natural` and `stress` are
byte-identical to before.

The film clip earned its place before shipping: it caught the first run design handing the
decoder the passage between two scenes, and the second dropping whole lines from run-sized
windows. Neither showed on the two older fixtures.

### Tier-B Content Bars Are Now Enforced

All 78 long-tail language fixtures declared a `min_word_overlap` that no test read; a
tier-B language could have regressed to gibberish while the suite stayed green. The bar is
now asserted -- as a fraction of the score a flawless transcript can reach, because the
text normaliser replaces combining marks with spaces and fragments the *reference* in some
scripts: a perfect Tamil transcript scores 0.43, so its declared 0.5 was unreachable. Tier-A
and combined ceilings are all 1.0, so their validated bars do not move.

### Bug Fixes

- **Per-window re-detection never ran on the default configuration.** The API resolves an
  auto-detected language before transcription unless vocal separation is enabled, so the
  pipeline saw a concrete language and concluded the caller had asked for it. `multilingual`
  was therefore off for every request on a default install -- the feature shipped in v1.3.0
  worked only with `--separation`. The caller's intent is now carried explicitly.
- **Gap filling invented speech in the pauses between clips.** It rescans at a looser VAD
  threshold than the decode uses, so it treated every deliberately-excluded silence as
  untranscribed speech and re-transcribed it, producing "Thank you very much." and "Bye-bye."
  in the gaps. Decoded spans now count as covered, and a gap is decoded in the language of
  the run it sits in rather than one detected on its own second of audio -- which, on real
  film, re-fractured a Japanese title from 8.7% to 19.9% foreign.
- **On a host with both a CUDA card and an Intel iGPU, every transcription ran on the CPU.**
  The scheduler keeps the Intel unit in the pool so vocal isolation can use it, and hands
  out units in rotation. Each auto-detect request runs language detection first: that
  took the CUDA unit and returned it to the back of the queue, so the transcription took
  the Intel unit -- where FASTER-WHISPER has no backend and silently loaded a second model
  on the CPU. Twenty times slower than the card beside it, with the banner reporting CUDA.
  An idle unit the engine can drive is now preferred; the CPU fallback happens only when
  the CUDA unit is genuinely busy, which is the case the pool rule was designed for.
- **`vad_filter` was passed twice** when clips applied -- a `TypeError` reachable only on that
  path, which no mocked test covered.
- **A priority language detection could deadlock a single-unit host.** A transcription
  asked to pause paused where it was -- between two segments, inside the worker stream --
  and kept the worker channel; the detection that had asked for the pause then waited for
  that channel, forever. Measured on the Intel NUC with real Bazarr traffic: one
  `/detect-language` during a long transcription left 41 requests queued and the health
  check unanswered for seven hours. Present since v1.3.0's isolated workers; this release's
  per-region detection made the window minutes wide on a CPU. A pause now releases the
  worker: region detection runs in chunks with the check between them, a paused decode
  closes its stream and resumes on what is left from the last consumed segment, and a
  pause during an isolated UVR pass cancels the separation and starts it again afterwards
  rather than holding the preprocessing worker.

## Known Limitations

### WhisperX and OpenAI-Whisper Return One Language Per File

All six code-switched fixtures fail on WHISPERX, and three of them were previously recorded as
passing because the bar was too low to notice: one *complete* leg scores about 0.50 and the
threshold was 0.40, so a file with half its content missing passed a test named
`transcribes_both_halves`. The bar is now 0.60, between the highest one-leg score measured
(0.50) and the lowest two-leg score (0.75).

This is architectural rather than a tuning problem. WhisperX commits to one language for a
whole file, and it accepts arbitrary decode options while forwarding none of them, so
`clip_timestamps` cannot reach it -- the option is on its unsupported list for that reason, and
the pipeline never offers clips to it. Manifest entries now carry `xfail_engines`, so the
defect is attached to the engine it belongs to and FASTER-WHISPER holds all six strictly.

OPENAI-WHISPER has the same shape with a smaller footprint: the reference implementation
detects the language once, on the first window, and decodes the whole file in it, and
decoding by speech region is a faster-whisper option it does not have. Measured on all six
clips on an RTX 5090, it drops the first leg of three (`mix_en_es` 0.38, `mix_en_fr` 0.50,
`mix_ar_fr` 0.50) and clears the bar on the other three, so those three entries are scoped
to both engines. If your material switches language inside a file, use the default engine.

### Cost

Decoding by region means more decode windows, and what that costs depends on the device: on
a CPU it is slower, roughly 2.3x on the stress fixture; on a GPU the windows are cheap and
skipping the silence between them can make it *faster*. Measured on the 20-minute stress
fixture -- the worst possible case by construction, since every adjacent utterance is a
different language and nothing legitimately merges:

| host | `ASR_SEGMENT_FIRST=0` | `=1` (default) |
| --- | ---: | ---: |
| RTX 5090 | 157s | **124s** (faster: no silence is decoded) |
| RTX 3080 laptop | 135s, 56/118 wrong-language windows | **198s, 0/118** (10 languages, 10 calls) |

The 56/118 is that row's own `=0` run through the service (validation row L7), not the 67/118
quoted above: that figure is the library-level spike on the same fixture, and the two runs
differ in temperature-fallback sampling, not in what they measure -- both are the baseline
missing roughly half the windows.
| Intel Core Ultra 7 CPU, int8 | 1248s (RTF 1.04) | 2873s (RTF 2.39) |
| laptop CPU, int8 | 1665s | 2913s |

Each language in a file is one decoder call, and every call recomputes the file's features,
which is cheap next to the encoder passes it then skips; a monolingual file is one call.
On a GPU it costs between nothing and +47%, well inside the real-time budget either way. On
CPU it multiplies wall clock by about 2.35 -- and CPU already misses the 1.0 budget on this
clip without it. A CPU deployment that needs the speed more than the two fixes can set
`ASR_SEGMENT_FIRST=false`, reintroducing exactly the wrong-language windows and silence
hallucinations measured above.

### A Single Foreign Line Is Decoded in the Language Around It

A block in another language becomes its own run only with 3 s of confident speech behind
it (or a fifth of a short clip's speech). A lone line under that -- "Bonjour" in an English
film -- is decoded in the surrounding language, because with the audio available it cannot
be told from the one-in-five mislabel that fractured monolingual film at 20%. Scenes in
another language, which are many seconds long, are decoded in their own.

### A Decode Window Is One Line

Each line is decoded in a window of its own, so a window starts without the sentence
before it. On a near-tie that can change a word: the 8-second accuracy fixture's first
sentence, a 3-second window on its own, comes back "A quick brown fox" where the whole-file
window reads "The" -- the two hypotheses 0.01 apart in log-probability. Two ways of giving
a window more context were measured and rejected on every long-form fixture: decoding a
file in one language as the whole-file call lost 126-220 of each monolingual fixture's
windows and invented speech in their silences, and joining lines under a second apart
lost 37-118. A window holding several lines drops lines; the article is the cheaper trade.

## Configuration

| Variable | Default | Description |
| :--- | :--- | :--- |
| `ASR_SEGMENT_FIRST` | `true` | Detect per region, group into runs, decode each language in its own call. FASTER-WHISPER; auto-detected requests and every translation |
| `ASR_FORCE_TRANSCRIPTION` | `false` | Transcribe the file's language, translate every other language in it into English; per request `force_transcription=` |
| `ASR_SEGMENT_LANGUAGES` | `true` | Report a language per run; the detection behind it always runs |
| `SEGMENT_RUN_MIN_SWITCH_SEC` | `3.0` | Confident speech a block in another language needs to become its own run |
| `SEGMENT_RUN_MIN_SWITCH_SHARE` | `0.2` | On a clip with under 15 s of speech, a block holding this share is enough |
| `SEGMENT_SPLIT_MIN_SILENCE_MS` | `250` | Silence that ends a speech region during the clip scan |
| `SEGMENT_SPLIT_PAD_MS` | `200` | Padding on each side of a clip, so no boundary cuts a word |
| `SEGMENT_FIRST_MIN_REGIONS` | `2` | Regions a file needs before clipping is worth it |
| `SEGMENT_CLIP_MERGE_GAP_SEC` | `0.3` | Real silence below this is a breath, and is rejoined |
